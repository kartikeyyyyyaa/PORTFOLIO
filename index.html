    Rule 01

    Measure, don’t guess.

    Benchmarks showed walkv’s pipelined writes were slower than plain ones: each command waited for its own disk sync. One batch per connection fixed it, with the same durability.

    Pipelined writes: 34k → 349k ops/s
    Rule 02

    Say when you’re unsure.

    PowerWatch shows an uncertainty band and a reliability flag next to every prediction. Sentinel reports cameras as live, faulty or never-checked, never a made-up uptime.

    Reliability flag: LOW, raised a day before the miss
    Rule 03

    Make it survive the demo.

    Foolscap runs fully without a database so a live demo can’t die. walkv gets killed mid-write on purpose, five rounds in a row, and has to come back with every write intact.

    Acknowledged writes lost: 0 of 102,519

    Break it yourself.

    My actual Go database, compiled to WebAssembly and running in your browser: the same log, checksum and recovery code as the server. Write some keys, then pull the plug. Or crash the whole page.
